# التحقق من نظام المباراة

تشغيل اختبارات منطق السيرفر المستقلة (يتطلب .NET SDK 10):

```powershell
dotnet run --project Tests/MatchRules/MatchRules.Tests.csproj
```

هذه اختبارات للقواعد فقط؛ لا تختبر Unity أو الفيزياء أو RPC أو معالجة NGO للسكربتات.

## إعداد Unity

- ابدأ من MainMenuScene باستخدام Unity 6000.4.7f1 وNGO 2.13.3.
- شغّل نسختين ثم أربع نسخ بحسابات Authentication مختلفة، باستخدام Multiplayer Play Mode أو builds منفصلة.
- في GameScene، MatchManager يحتفظ بنقاط البداية الأربع الأصلية وبالترتيب 0، 2، 1، 3. لا تغيّر صلاحية NetworkTransform من Owner.
- راجع Team1Base: teamIndex=0، وTeam2Base: teamIndex=1. الثانية نسخة من مكعب القاعدة الموجود في الملف المحفوظ، عند الموقع المقابل؛ راجع موقعها وشكلها وفق تصميم المستوى.
- teamBases في MatchManager مرتبط بالقاعدتين، وصحة كل قاعدة maxHealth=1000، وتأثير BigExplosion مربوط. يمكن تعديل الصحة من Inspector.
- مدد MatchManager الافتراضية regulationDuration=300، overtimeDuration=120، respawnDelay=3. لتسريع اختبارات الحدود مؤقتًا استخدم 15، 10، 3 ثم أعد 300، 120، 3.
- MatchHud مربوط في المشهد بخط TMP؛ ينشئ المؤقت والنتائج وزر Back وقت التشغيل. لا تضف Canvas أو EventSystem آخر يدويًا لهذا النظام.

## سيناريوهات Play Mode المطلوبة

| السيناريو | النتيجة المطلوبة |
|---|---|
| لاعبان ثم 2v2، مع الضغط على الحركة والإطلاق أثناء التحميل | يبقى التحكم محجوبًا؛ يبدأ 05:00 بعد جاهزية الجميع؛ المواقع والفرق الأصلية صحيحة. |
| إطلاق على زميل وعلى قاعدة الفريق، أثناء الوقوف والحركة | لا يتغير HP، ولا تظهر دفعة أو تأثير إصابة على الصديق؛ الرصاصة Trigger وتستمر عبر الهدف الصديق. |
| قتل خصم وقاعدته سليمة | Death واحدة وKill واحدة؛ عداد 3 ثوانٍ؛ عودة إلى نقطة اللاعب نفسها بصحة كاملة ودون سرعة متبقية؛ الكاميرا والتصويب يعملان. |
| تدمير القاعدة خلال عداد العودة | إلغاء العودة، رسالة Eliminated، وبقاء المؤقت؛ راجع أيضًا التدمير لحظة انتهاء العدّاد ومع تأخير الشبكة. |
| تدمير القاعدة وآخر لاعب من الفريق ما زال حيًا | لا يموت اللاعب ولا تنتهي المباراة لهذا السبب وحده؛ موته التالي لا يسمح بالعودة. |
| قتل كل أعضاء الفريق وقاعدتهم سليمة | لا يخسرون مع وجود عودة مسموحة ومعلقة. |
| انتهاء المرحلة الأساسية | تدمير القاعدتين معًا وإلغاء جميع العودات؛ Overtime مع 02:00؛ لا يوجد Respawn. |
| انتهاء الوقت الإضافي مع أحياء من الفريقين / إقصاء فريق خلاله | Draw في الأولى؛ فوز الفريق القادر على الاستمرار في الثانية. |
| قاعدتان مدمّرتان ورصاصتان قاتلتان في خطوة الفيزياء نفسها | Draw؛ لا يعتمد الفوز على ترتيب الاصطدامات؛ جرّب Host وClient كمطلقين. |
| عدة عمليات موت وعودة، وموت المطلق قبل وصول رصاصته | إحصائيات تراكمية دقيقة؛ القتل يُنسب للمطلق الأصلي؛ تدمير قاعدة لا يمنح Kill. |
| انقطاع Client حي أو منتظر للعودة | يُزال من حساب الأحياء والعودة، وتبقى إحصائياته؛ إذا استمرت المباراة، يجب أن يستطيع الآخرون التحرك والإطلاق. إذا خرج Host أثناء مباراة جارية، تظهر حالة انقطاع لدى العملاء دون نتيجة مخترعة. |
| انتهاء المباراة ورصاصات ما زالت في الجو | يتوقف الضرر والتحكم والعودة، ولا تتغير الإحصائيات أو النتيجة. |
| Client يضغط Back من النتائج | يرجع هو وحده إلى RoomBrowserPanel؛ يبقى الآخرون في النتائج. |
| Host يضغط Back فور ظهور النتائج، مع تأخير شبكة | ينتظر تأكيد حفظ النتائج من العملاء ضمن مهلة؛ تبقى النتائج لديهم بعد انقطاعه، ولكل منهم Back مستقل. |
| مباراة جديدة بعد العودة | لا توجد نسخ دائمة مكررة؛ الاسم وتسجيل الدخول محفوظان؛ النتائج القديمة لا تظهر؛ الإحصائيات تبدأ من الصفر. |

أعد الاختبارات الفيزيائية والعودة مع تأخير 100–300ms وjitter، من منظور Host وClient. راقب Console لأخطاء RPC/Teleport أو مهلة إعادة التموضع. لم يُجرَ اختبار متعدد اللاعبين فعليًا داخل البيئة الحالية بسبب تعذّر تشغيل Unity أثناء تهيئة الترخيص.
