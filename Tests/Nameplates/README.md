# أسماء اللاعبين: التحجيم المحلي حسب المسافة

**ضبط المدى الحالي:** أضيف حد ظهور محلي قدره 18 وحدة، بتقدير من المسافة بين نهاية الجزيرة الوسطى والجزيرة المقابلة. ليس هناك شرط جزيرة أو trigger. تصبح نتيجة Present هي قرار الظهور، ويطبّقه PlayerNameDisplay على Canvas الاسم قبل رسم الكاميرا؛ اسم المالك يبقى مخفيًا. يبدأ Canvas مخفيًا عند Spawn حتى أول تقييم للكاميرا، لتجنب ظهور اسم بعيد مؤقتًا.

نجح **37 فحصًا** للنسخة الحالية في Unity Play Mode؛ النتيجة `range-checks.txt`. تشمل الحدود 18 و18.01، الحجم داخل المدى، الإخفاء والعودة، التكرار وعدم تراكم المقياس، وإعادة التهيئة وتبديل الكاميرا. لقطتا `Range/center-hidden.png` و`Range/edge-visible.png` على نسخة من Prefab المؤلف وكاميرا GameScene: الاسم مخفي عند 24.75 وحدة وواضح عند 16.75 وحدة، مع تطبيق توجيه الاسم والتحجيم يدويًا في فحص العرض المعزول. لم تُعد جلسة Host/عميلين بهذا الحد الجديد؛ نتائج VerifiedSession أدناه تخص الإعداد السابق دون حد ظهور.

## التنفيذ والإعداد

`PlayerNameDistanceScale.cs` مكوّن عرض محلي عادي (ليس NetworkBehaviour). أضيف عبر Unity MCP إلى `NameTagCanvas` داخل `Assets/ProjectsFiles/Prefabes/Player.prefab`. مرجع `nameVisual` الحالي يشير إلى `PlayerNameTextBackground` الذي أضافه المستخدم، ليُحجَّم مع النص التابع له كوحدة واحدة. يحتفظ بالمقياس المؤلف عند Awake ويشتق كل قيمة لاحقة منه، دون تراكم الضرب.

`PlayerNameDisplay.cs` يحتفظ بمسؤولية النص وقاعدة إخفاء اسم المالك. يستخدم حدث URP `beginCameraRendering` بدل البحث عن Camera.main كل إطار، ويطبق توجيه الاسم والتحجيم بالكاميرا الفعلية التي سترسمه. يقبل كاميرا Game مفعّلة وموسومة MainCamera فقط، ويعمل على نسخ اللاعبين البعيدين عند كل عميل بما فيه Host. لا يقبل كاميرات Scene View أو المعاينة أو الانعكاسات.

رُبط `distanceScale` و`nameCanvas` في Prefab عبر Unity MCP. مرجع Canvas صريح لأن خاصية TMP.canvas قد تكون null إذا كان Canvas معطلاً عند إعادة Spawn. يُخفى اسم المالك بتعطيل Canvas فقط، مع إبقاء NetworkBehaviour فعالاً لإعادة الاستخدام. الاشتراكات تُنظف عند التعطيل/Despawn، ويُستعاد مقياس النص الأصلي. لا توجد RPC أو NetworkVariable أو تعديلات على NetworkTransform لهذه الميزة.

| Inspector على NameTagCanvas / PlayerNameDistanceScale | الافتراضي |
|---|---:|
| Nearby Base Scale | 6 |
| Enlargement Start Distance | 5 |
| Maximum Scale Distance | 16 |
| Maximum Scale Multiplier | 3.2 |
| Maximum Visible Distance | 18 |
| Smoothing Speed | 10 |

Nearby Base Scale هو معامل للمقياس المؤلف، وليس ارتفاع النص بوحدات العالم. لتكبير كل الأسماء أكثر يمكن تغييره من 6 إلى 7. Maximum Scale Multiplier يُقاس بالنسبة للحجم القريب. Maximum Visible Distance يحدد مدى الظهور لكل مشاهد؛ تقليله يؤخر ظهور الاسم حتى الاقتراب أكثر. Smoothing Speed=0 يعطل التنعيم؛ القيم الأكبر تستجيب أسرع.

```
t = clamp01((distance - startDistance) / (maximumDistance - startDistance))
multiplier = nearbyBaseScale * lerp(1, maximumScaleMultiplier, t)
localScale = authoredScale * smoothedMultiplier
```

بالقيم الحالية: حتى 5 وحدات يكون المعامل 6، وعند 10.5 يكون 12.6، ومن 16 حتى 18 يكون 19.2 كحد أقصى، وبعد 18 يختفي الاسم. الانتقال خطي ليعوض المسافة؛ التنعيم أُسّي باستعمال الوقت غير المتأثر بـtimeScale. تبديل الكاميرا أو العودة إلى المدى يطبق الحجم الصحيح مباشرة، بدلاً من نقل حالة تنعيم المشاهد السابق.

لا تغيير في fontSize أو النص أو الألوان أو المادة المشتركة أو مقياس Canvas أو الدبابة. لا بحث مشهدي أو تخصيص قائمة أو استنساخ مادة كل إطار. لا إنشاء UI في وقت التشغيل.

## جلسة الشبكة السابقة، قبل إضافة حد الظهور

`ValidationSession.cs.txt` مصدر أداة Editor مؤقتة استُخدمت مع Multiplayer Play Mode: Main Editor كـHost وعملتا Editor إضافيتان كعميلين مستقلين عبر Unity Transport محلي على 127.0.0.1:17877. لم تكن محاكاة ثلاث كاميرات في عملية واحدة. الأداة تستخدم Prefabs الموجودة، ولا تنشئ UI. تُنسخ مؤقتًا إلى Editor folder أثناء الاختبار ثم تُزال من Assets.

الجلسة تعزل Player prefab عن lobby/Relay وإدارة المباراة ومزامنة NetworkObjects الخاصة بالمشهد. يتم تثبيت تشكيل اللاعبين للاختبار فقط. بالتالي ليست اختبار انضمام مباراة كاملة أو gameplay/physics أو build مستقل. اللقطات لا تشمل واجهات Screen Space Overlay.

المراحل: 0 = A/B قريبان وC بعيد؛ 1 = C يقترب؛ 2 = عودة C للبعد وتبديل كاميرا اللعب؛ 3 = Host ينفذ Despawn(false) ثم SpawnAsPlayerObject(1) لإعادة استخدام B. التقارير تقارن الحجم الفعلي بالمسافة من كاميرا العملية نفسها، وتفحص إخفاء اسم المالك وثبات rootScale وCanvas scale.

نتائج الشبكة النهائية المعتمدة واللقطات تُحفظ في `VerifiedSession`. نتائج المحاولات التشخيصية الأولى ليست دليلاً على نجاح النسخة النهائية.

**النتيجة النهائية: PASS في 12 تقريرًا (4 مراحل × 3 عمليات).** في المرحلة 0 رأى Host/A اسم B بمعامل 4 عند مسافة 4.47، ورأى B اسم A بمعامل 4 عند 2.83. رأى C الاسمين بمعامل 24 عند نحو 45–48 وحدة. في المرحلة 1 رجعت الأسماء القريبة إلى نحو 4 مع التنعيم. نجحت الكاميرات البديلة في المرحلة 2 وإعادة استخدام B شبكيًا في المرحلة 3، مع استمرار إخفاء اسم المالك وثبات مقياس الدبابة (10,10,10) وCanvas (1,1,1). سماحية مقارنة التنعيم 0.15 في معامل الحجم؛ ليست كل قيمة عابرة مساوية تمامًا للهدف.

لم تظهر أخطاء في Console الرئيسي خلال الجولة النهائية؛ المحاولات السابقة كشفت مشكلة TMP.canvas عند إعادة الاستخدام، وصُححت بالمرجع الصريح وأعيد الاختبار. لم تُختبر جلسة Lobby/Relay أو build مستقل أو أداء GPU/GC بقياس Profiler. لم يُضف نظام لمنع تداخل الأسماء عندما تتراكب اتجاهاتها على الشاشة.
